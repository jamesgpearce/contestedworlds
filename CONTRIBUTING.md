# Correcting the historical record

Historical corrections are welcome. You can make a dataset-only pull request without editing React, SVG, or CSS.

1. Open the relevant file in `data/islands/`. Each island has one ordinary, two-space-indented JSON file.
2. Correct the date, explanation, or political power. Keep events in chronological order and preserve existing event IDs, even when a correction changes their order. New IDs must be unique and start with the island ID plus a hyphen; they do not need to be sequential.
3. Cite the evidence using an ID from `data/sources.json`, or add a bibliography entry there. Prefer the relevant passage in a treaty, local historical study, museum, library, or government history. Explain conflicting evidence in `uncertainty` rather than silently choosing an exact day.
4. Run `npm run data:check`. Python 3 is the only dependency for this check; no npm installation is necessary when running `python3 scripts/build-data.py --check` directly.
5. Describe the correction, your evidence, and its geographic extent in the pull request. The included GitHub Actions workflow validates the data and builds the visualization.

Please do not edit generated `lib/caribbean.json` or `public/data/` files. The development and production commands regenerate them. A change to an island file produces a small reviewable diff; calculated counts, inherited states, and SVG geometry are generated by code.

## Event fields

```json
{
  "id": "saint-lucia-12",
  "date": "1763-02-10",
  "precision": "day",
  "kind": "treaty",
  "title": "Paris awards Saint Lucia to France",
  "detail": "The peace settlement recognized French possession of Saint Lucia.",
  "controller": "france",
  "sovereign": "france",
  "sources": ["paris1763", "ws-lucia"]
}
```

- `date`: `YYYY`, `YYYY-MM`, or `YYYY-MM-DD`. Do not invent a month or day to fill a field.
- `precision`: `year`, `month`, or `day`, matching the date; use `circa` with a year and an `uncertainty` explanation for an approximation.
- `controller`: the new principal administration, or `null` when administration does not change.
- `sovereign`: the new recorded sovereign title, or `null` when the title does not change. Occupation does not automatically annex an island.
- `kind`: `settlement`, `capture`, `restoration`, `treaty`, `independence`, `withdrawal`, `context-change`, `resistance-change`, `claim`, `context`, `resistance`, or `status`.
- `claim`, `context`, `resistance` and `status` are annotations: both power fields must be `null`. A claim also needs `claimant`.
- `sources`: at least one bibliography ID. `uncertainty` and `qualification` are optional explanatory text displayed in the explorer.

Power IDs are defined in `data/owners.json`. The name of that file reflects the original research question; the dataset and interface deliberately distinguish several meanings of “ownership.” See `data/methodology.md` for the editorial policy and scope. An initial Indigenous line does not imply a single ancient state or erase surviving Indigenous peoples.

## What validation can establish

The compiler rejects invalid dates, contradictory date precision, duplicate JSON keys or IDs, unknown powers, missing citations, out-of-order events, and claims that accidentally transfer control. It validates the complete dataset before writing any output. Regression tests also check the plotting contracts and the treatment of occupations and treaty-only transfers.

These checks establish structural integrity, not historical truth. The evidence and interpretation still need human review. If well-supported new research contradicts a historical regression fixture, update the fixture and explain why in the same PR.

## Adding a track

Add an island file and list its ID in `data/scope.json`; add a modern place there only if it expands the geographic scope. Keep an explicit note when a track represents a principal island or an archipelago. The chart derives its data and counts from the compiled records.
